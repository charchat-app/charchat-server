# CREATE-US-09 재분류 배치

- 기본 정보 직접 저장과 공통 저장(임시본 확정 포함)은 같은 `story_basic.apply_basic`을 거친다. 확정 세계관 또는 캐릭터 상세·구성이 달라지면 같은 트랜잭션에서 스토리를 분류 필요로 표시한다. 캐릭터 이름·정렬만 바뀌거나 기타 입력이 바뀌는 경우는 표시하지 않는다. 등록 스토리의 임시 편집본은 확정 전에는 읽지 않는다.
- `run_cycle`은 기존 유효 결과가 있고 분류 필요로 표시된 활성 등록 스토리를 주기당 한 번 수집한다. 실제 분류 시 최신 확정본의 세계관·캐릭터 상세만 전달한다. 성공한 최신 결과만 스토리 단위로 교체하고 표시를 해제한다.
- `run_hourly`의 기본 실행 간격은 3,600초다. 운영 연결 시 **DB당 스케줄러 1개**만 실행한다. DB 잠금이 막는 것은 두 배치의 동시 실행이며, 독립 타이머를 여러 개 띄우면 시간 간격까지 보장하지 않는다.
- 최초 등록은 `create_app(category_classifier=...)`로 분류기를 명시한 경우에만, 확정 저장 응답 뒤 별도의 연결로 분류한다. 최초 분류와 재분류는 같은 입력 범위·결과 저장 규칙을 사용한다. 기본 `app.main:app`에는 분류기가 연결되어 있지 않다.
- 시간 배치는 운영에 연결하지 않았다. 최초 유효 결과가 없는 스토리(최초 분류 실패 후 수정한 경우 포함)는 시간 배치에서 건드리지 않는다. 최초 분류의 영속 전달·복구, 실패 상태 및 상한 있는 자동 재시도를 추가한 뒤 활성화해야 한다. 이 코드만 상시 가동하면 기존 결과가 있는 스토리의 실패가 다음 주기에도 다시 선택될 수 있다.
